1. So funktioniert es

Die App selbst bleibt eine statische Website bei Vercel. Nur die Seite „Ankündigungen" fragt beim Öffnen eine Tabelle bei Supabase ab und zeigt, was dort steht. Eine neue Ankündigung ist deshalb ohne Deployment sichtbar, sobald jemand die Seite neu lädt. Ohne Netz zeigt die Seite die zuletzt geladene Kopie mit ihrem Stand.

  • Lesen darf jeder, aber nur Einträge mit sichtbar = an. Der Schlüssel dafür steht ohnehin in jedem Browser, er ist dafür gemacht.
  • Schreiben geht nur im Supabase-Dashboard. Über die App oder die Schnittstelle kann niemand etwas ändern. Das ist in der Datenbank selbst festgelegt (Row Level Security).

Den geheimen Schlüssel nie herausgeben. Supabase zeigt zwei Arten: publishable (darf in die App) und secret bzw. service_role (umgeht jeden Schutz). In Vercel, in .env und in der App steht nur der veröffentlichbare.

2. Was noch gebraucht wird

3. Projekt anlegen

  1. Auf supabase.com/dashboard registrieren, Zwei-Faktor-Anmeldung einschalten (Account → Security).
  2. New organization, z. B. „ASeV Jahrestagung", Tarif nach Schritt 2. Den zweiten Entwickler unter Team einladen.
  3. New project:
    • Name: altstipendiaten-jahrestagung
    • Database Password: Generate a password und im Passwortmanager ablegen. Es wird für die App nicht gebraucht, aber für Notfälle und die Kommandozeile.
    • Region: Central EU (Frankfurt)
    • Unter Security bzw. den erweiterten Optionen: Data API eingeschaltet lassen. Darüber liest die App.
  4. Warten, bis das Projekt bereit ist (1–2 Minuten).

4. Tabelle anlegen

  1. Im Repository die Datei supabase/migrations/20261122000000_ankuendigungen.sql öffnen und den ganzen Inhalt kopieren.
  2. In Supabase links SQL Editor → New query → einfügen → Run. Erwartet: „Success. No rows returned".
  3. Table Editor öffnen. Die Tabelle ankuendigungen ist da. Neben dem Namen steht nicht „RLS disabled" bzw. „Unrestricted".

Spätere Änderungen an der Struktur kommen als neue Datei in supabase/migrations/, per Pull Request mit Review, und werden genauso im SQL Editor ausgeführt. Alternativ mit der Kommandozeile: npx supabase link und npx supabase db push.

5. Adresse und Schlüssel

  • Projektadresse: Project Settings → Data API (oder Startseite des Projekts, „Project URL"). Sie hat die Form https://xxxxxxxx.supabase.co.
  • Veröffentlichbarer Schlüssel: Project Settings → API Keys → Publishable key (beginnt mit sb_publishable_). Bei älteren Projekten heißt er anon public und beginnt mit eyJ. Beides funktioniert.

6. In Vercel eintragen

  1. Vercel → Projekt → Settings → Environment Variables:
    • PUBLIC_SUPABASE_URL = Projektadresse
    • PUBLIC_SUPABASE_KEY = veröffentlichbarer Schlüssel
    Jeweils für Production und Preview. Nicht als „Sensitive" markieren nötig: Die Werte stehen später ohnehin im Quelltext der Seite.
  2. Die Werte wirken erst nach dem nächsten Bauen: GitHub → Actions → Deployment → Run workflow und freigeben. Vorschauen bekommen sie mit dem nächsten Push.
  3. Lokal: .env.example nach .env kopieren und dieselben Werte eintragen. .env wird nie committet.

7. Schutz prüfen

Im Terminal, mit den Werten aus Schritt 5:

URL=https://xxxxxxxx.supabase.co
KEY=sb_publishable_…

# Lesen: erlaubt, liefert nur sichtbare Einträge
curl -s "$URL/rest/v1/ankuendigungen?select=titel,sichtbar" -H "apikey: $KEY"

# Schreiben: muss scheitern
curl -s -X POST "$URL/rest/v1/ankuendigungen" -H "apikey: $KEY" \
  -H "Content-Type: application/json" -d '{"titel":"Test","text":"Test"}'

Erwartet: beim Lesen [] oder nur Einträge mit "sichtbar":true. Beim Schreiben eine Fehlermeldung mit permission denied for table ankuendigungen. Kommt beim Schreiben etwas anderes zurück, ist die Tabelle ungeschützt. Dann Schritt 4 wiederholen.

8. Eine Ankündigung veröffentlichen

Für alle, die Ankündigungen schreiben:

  1. supabase.com/dashboard → Projekt → Table Editor → ankuendigungen.
  2. Insert → Insert row:
    • titel: kurz und eindeutig, z. B. „Raumänderung am Freitag"
    • text: die Nachricht, Zeilenumbrüche sind erlaubt
    • gewicht: info oder wichtig. „Wichtig" erscheint mit roter Marke. Sparsam verwenden, sonst nutzt es sich ab.
    • sichtbar: zunächst aus lassen (false)
    • Die übrigen Felder füllt Supabase selbst.
    → Save.
  3. Text noch einmal lesen, dann in der Zeile sichtbar auf true setzen. Ab jetzt sieht jeder die Ankündigung, der die Seite neu lädt.
  4. In der App unter „Ankündigungen" kontrollieren.

Ändern und zurückziehen

  • Ändern: Zelle im Table Editor anklicken, bearbeiten, speichern.
  • Zurückziehen: sichtbar auf false. Besser als löschen, weil der Text erhalten bleibt.
  • Reihenfolge: Neueste stehen oben, maßgeblich ist veroeffentlicht_am.

Wer die Seite schon offen hat, sieht die Änderung erst nach dem Neuladen. Geräte ohne Netz zeigen den zuletzt geladenen Stand und sagen dazu, von wann er ist. Für wirklich dringende Änderungen vor Ort zusätzlich einen zweiten Weg nutzen (F9).

9. Zugänge für das Orga-Team

Supabase kennt keine Rolle „darf nur Ankündigungen schreiben". Wer den Table Editor benutzen kann, hat Zugriff auf das ganze Projekt.

Eine eigene Pflegeoberfläche mit fein begrenzten Rechten ist möglich, setzt aber geklärte Rollen voraus (F3, F8). Siehe ADR-0014.

10. Fehlerbehebung

Die Seite zeigt … Ursache und Abhilfe
„noch nicht mit der Datenbank verbunden" PUBLIC_SUPABASE_URL oder PUBLIC_SUPABASE_KEY fehlten beim Bauen. In Vercel eintragen, dann neu deployen (Schritt 6).
„konnten gerade nicht geladen werden" Projekt pausiert (Dashboard zeigt „Paused" → Restore), Schlüssel falsch oder gelöscht (Antwort 401), oder das Gerät ist offline. Mit dem curl-Befehl aus Schritt 7 prüfen.
Eine Ankündigung fehlt sichtbar steht auf false, oder die Seite wurde noch nicht neu geladen.
„Keine Verbindung – angezeigt wird der Stand vom …" Das Gerät erreicht Supabase gerade nicht. Kein Fehler der App.

11. Laufender Betrieb

Pausieren

Im kostenfreien Tarif pausiert Supabase Projekte nach etwa einer Woche ohne Aktivität und schickt vorher eine E-Mail. Wiederherstellen: Dashboard → Projekt → Restore project. Vor und während der Tagung regelmäßig nachsehen, oder einen Tarif ohne Pausieren wählen.

Schlüssel wechseln

Project Settings → API Keys → neuen veröffentlichbaren Schlüssel anlegen, in Vercel eintragen, neu deployen, danach den alten löschen. Geräte mit einer alten Version der Seite zeigen bis zum Neuladen die Kopie.

Datensicherung

Was der Tarif sichert, steht unter Database → Backups. Ankündigungen sind kurzlebig. Wichtig ist vor allem, dass die Tabellenstruktur im Repository liegt und sich jederzeit neu anlegen lässt (Schritt 4).

Nach der Tagung

Klären, ob das Projekt bestehen bleibt oder gelöscht wird, und wer es verwaltet (F2).
