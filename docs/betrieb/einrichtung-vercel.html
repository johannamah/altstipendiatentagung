1. Überblick und Reihenfolge

Die App ist eine statische Website. Für jeden Pull Request baut Vercel über seine Git-Anbindung eine Vorschau. Live geht nur, was auf main gemergt und im GitHub Environment production freigegeben ist. Das erledigt der Workflow Deployment. Die Ankündigungen lädt der Browser direkt aus Supabase. Die Einrichtung dafür steht in einrichtung-supabase.html.

Kein echter Vorabschutz. Vercel schützt im kostenfreien Tarif die eigene Domain nicht. Bis zum Go-Live hält nur die Zugangsabfrage (ADR-0010) Suchmaschinen und weitergereichte Links ab. Wer den Quelltext liest, kommt daran vorbei. Unfreigegebene Namen und Bilder (F14, F16) gehören deshalb nicht in die App.

5. Domain in Vercel hinzufügen

  1. Settings → Domains → Add Domain, altstipendiaten-jahrestagung.de eingeben.
  2. Vercel bietet an, auch www.altstipendiaten-jahrestagung.de hinzuzufügen. Die Option „Redirect www to altstipendiaten-jahrestagung.de" wählen. Bei der Domain www lässt sich der Statuscode auf 301 stellen (Standard: 308). Beides funktioniert.
  3. Vercel zeigt bei beiden Domains „Invalid Configuration" und die benötigten DNS-Einträge, typischerweise:
    • für die Domain: Typ A, Wert eine IP-Adresse von Vercel
    • für www: Typ CNAME, Wert ein Name auf vercel-dns.com
    Die angezeigten Werte abschreiben. Vercel vergibt sie je Projekt, sie können von älteren Anleitungen im Netz abweichen.

6. DNS-Einträge bei Strato

Die Nameserver bleiben bei Strato, geändert werden nur zwei Einträge. Strato ändert seine Oberfläche gelegentlich, die Menünamen können abweichen.

  1. Im Strato-Kunden-Login anmelden und das Paket mit der Domain wählen → Domains → Domainverwaltung.
  2. Bei altstipendiaten-jahrestagung.de auf das Zahnrad bzw. Verwalten → Reiter DNS.
  3. A-Record: verwalten → „Andere IP-Adresse" → die IP aus Vercel eintragen → speichern.
  4. AAAA-Record (IPv6): Steht dort ein Eintrag, ihn entfernen bzw. deaktivieren. Vercel bietet für eigene Domains kein IPv6 an. Ein alter Eintrag schickt Geräte mit IPv6 sonst weiter zu Strato.
  5. www: Unter Domainverwaltung eine Subdomain www anlegen, falls es sie nicht gibt. Dann bei der Subdomain → DNS → CNAME-Record → den Namen aus Vercel eintragen. Der A- und AAAA-Eintrag der Subdomain entfällt damit.
  6. Prüfen, dass bei der Domain keine Strato-Umleitung und kein Webspace aktiv ist, der die Einträge überschreibt.
  7. Nicht anfassen: MX-, TXT- und SPF-Einträge. Sie gehören zu E-Mail.

Nach 10 Minuten bis einigen Stunden zeigt Vercel bei beiden Domains „Valid Configuration" und stellt das Zertifikat selbst aus. Prüfen im Terminal: 

dig A altstipendiaten-jahrestagung.de +short
dig AAAA altstipendiaten-jahrestagung.de +short
dig CNAME www.altstipendiaten-jahrestagung.de +short

Erwartet: die IP aus Vercel, keine Ausgabe für AAAA, der Name aus Vercel für www.

7. Token und Kennungen für GitHub

Token

  1. Account Settings → Tokens → Create Token.
  2. Name github-actions-altstipendiatentagung, Scope: das Team bzw. Konto, in dem das Projekt liegt, Ablauf: ein Datum nach der Tagung, z. B. Ende Juni 2027.
  3. Das Token wird nur einmal angezeigt. Direkt in GitHub eintragen (Schritt 8) und im Passwortmanager ablegen.

Kennungen

  • Project ID: Projekt → Settings → General → Project ID (beginnt mit prj_).
  • Org ID: bei einem Team Team Settings → General → Team ID (beginnt mit team_), bei einem persönlichen Konto Account Settings → General → Vercel ID.

Alternativ schreibt npx vercel link beide Kennungen nach .vercel/project.json. Der Ordner steht in .gitignore und wird nicht committet.

8. GitHub einrichten

Das braucht Admin-Rechte am Repository, also johannamah.

Environment production

  1. Settings → Environments → New environment, Name genau production.
  2. Required reviewers: beide Entwickler, Prevent self-review anhaken.
  3. Deployment branches and tags: Selected branches → main.
  4. Environment secret: VERCEL_TOKEN = Token aus Schritt 7.
  5. Environment variables:
    • VERCEL_ORG_ID = Org ID
    • VERCEL_PROJECT_ID = Project ID
    • VORABZUGANG = aktiv. Der Workflow prüft dann nach jedem Deployment, dass die Zugangsabfrage greift. Fehlt die Variable, gilt ebenfalls aktiv.

9. Erstes Deployment

Voraussetzungen: Schritte 3 bis 8 erledigt, beide Domains in Vercel mit „Valid Configuration".

  1. PRs reviewen und mergen: #16 (Jetztkarte), danach bei den aufbauenden PRs die Basis auf main umstellen und sie nacheinander mergen.
  2. Actions → Deployment zeigt „Produktion" als Waiting. Die andere Person → Review deployments → production → Approve and deploy.
  3. Der Job prüft, holt die Vercel-Einstellungen, baut, deployt und ruft die Adresse ab.

10. Go-Live (geplant Anfang Dezember 2026)

Erst wenn alles aus „Vom Vorstand" in Schritt 2 erledigt ist und das Go vorliegt:

  1. PR mit den letzten Textänderungen: Platzhalterhinweis der Datenschutzerklärung entfernen, Datum eintragen, mergen und deployen.
  2. Vercel → Settings → Environment Variables → ZUGANGSWORT löschen.
  3. GitHub → Environment production → Variable VORABZUGANG auf aus.
  4. GitHub → Actions → Deployment → Run workflow (Branch main) und freigeben. Die Prüfung erwartet jetzt eine Seite ohne Sperre.
  5. Im privaten Fenster öffnen und die Seiten durchklicken.

11. Fehlerbehebung

Meldung Ursache und Abhilfe
„The specified token is not valid" / „No existing credentials found" Secret VERCEL_TOKEN fehlt, ist abgelaufen oder gehört zu einem anderen Konto. Neues Token nach Schritt 7.
„Project not found" VERCEL_ORG_ID oder VERCEL_PROJECT_ID falsch, oder das Token hat keinen Zugriff auf dieses Team.
„Vorabzugang ist aktiv, aber die Seite hat keine Zugangsabfrage" ZUGANGSWORT fehlt in Vercel für Production, oder es wurde nach dem Bauen angelegt. Variable prüfen, Workflow erneut starten. Bis dahin ist die Seite ohne Abfrage erreichbar.
Vercel zeigt „Invalid Configuration" DNS bei Strato noch nicht übernommen oder falscher Wert. Mit dig prüfen (Schritt 6). Häufig steht noch ein AAAA-Eintrag.
„/sw.js wird zwischengespeichert" Die Kopfzeilen aus vercel.json greifen nicht. Datei und Projekt-Root prüfen.
„www leitet nicht dauerhaft … weiter" Schritt 5: Weiterleitung bei der Domain www in Vercel prüfen.
Ein Push auf main erscheint in Vercel als Production-Deployment Die Git-Anbindung ignoriert vercel.json. Prüfen, ob die Datei auf main liegt. Bis dahin baut Vercel main selbst, ohne Freigabe.

12. Laufender Betrieb

Zurück auf einen früheren Stand

Vercel → Projekt → Deployments → bei einer früheren Production-Version Instant Rollback. Danach den Fehler per PR beheben. Das nächste Deployment von main überschreibt den Rollback.

Zugangswort wechseln

Variable in Vercel ändern, Workflow erneut starten. Alle Geräte müssen das neue Wort einmal eingeben.

Token erneuern

Vor Ablauf ein neues Token erzeugen, das Secret in GitHub ersetzen und das alte Token in Vercel löschen. Das gilt auch sofort, wenn jemand ausscheidet oder das Token sichtbar geworden ist.

Nach der Tagung

Klären, wer Vercel-Projekt, Supabase-Projekt und Domain übernimmt (F2). Die Domain bei Strato verlängert sich weiter, auch wenn niemand mehr die App pflegt.
